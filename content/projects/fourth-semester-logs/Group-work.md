Experience of working together as a group with agents:

This project we have been using agents to code most of our code base. During these weeks of project I feel like I have taken some valuable experience with me. It is not easy to work together as a group with agents. I found it to be hard of not clashing with others work. To be fair we did mostly get it to be relatively conflict free but we had to be very specific with the agent of what it can touch and what it can't. 
We had strict rules of pull requests and branches which made it easier to work with. 

But I can't get the feeling of being in a larger groups brings more restrictions to what you can set the agent to work with. I don't have examples of this because we had to restrict ourselves to the rules that we made. 

Besides the PR's, branches and personally no github worktrees, we had the AGENTS.md, ARCHITECTURE.md and CODESTANDARD.md that we would reference in every single ticket. We did not have a spec document to help the agents keep track and I didn't have one for the things that I put my self on. I felt like I had a hard time designing that document and see how it could help? Maybe thats because we didnt work with worktrees and we took the features branch by branch. 

That is another point I would like to touch upon that we did not build the biggest project out there. I had a hard time working with these agents. What is allowed, how tight/restricted should these tickets be. Stuff like that put a halt on the progress on development at least for me.

When working in a group with agents its very essential to keep communication up to a certain standard. There were times where the communication halted or lacked. But that is not different from a "normal" project.
